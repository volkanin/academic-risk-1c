# Настройка Moodle для выгрузки данных о студентах

Справка для администратора СЭО Moodle: подготовка веб-служб, из которых
сервис раннего предупреждения читает сведения об учебном процессе.
Формат обращения: REST API, POST на webservice/rest/server.php с wstoken,
формат json. Прямой доступ к базе Moodle не используется (FR-13 в
docs/requirements.md). Персональные данные не выгружаются: из профиля
пользователя читается только логин, в хранилище проекта он сразу
заменяется sha256-хешем с солью, имена и почты отбрасываются (NFR-2,
п. 9 ТЗ).

## Что выгружается

| Данные | Функции веб-служб |
|---|---|
| Список курсов | core_course_get_courses |
| Участники курса, время последнего входа в курс | core_enrol_get_enrolled_users |
| Задания и сданные работы с временем сдачи | mod_assign_get_assignments, mod_assign_get_submissions |
| Тесты и попытки со временем завершения | mod_quiz_get_quizzes_by_courses, mod_quiz_get_user_attempts |
| Форумы и обсуждения со временем создания и последнего ответа | mod_forum_get_forums_by_courses, mod_forum_get_forum_discussions |
| Элементы оценок по студентам | gradereport_user_get_grade_items |
| Сведения о службе (проверка связи, необязательна) | core_webservice_get_site_info |

Журнал событий core_log_get_logs в ветке Moodle 4.5 не объявлен как внешняя
функция, поэтому активность собирается временами действий: сдача работы,
завершение попытки теста, сообщение на форуме. Временные метки действий
дают недельную динамику активности, а сами действия содержательнее просмотров
страниц для признаков риска.

## Подключение

1. Включить веб-службы: Администрирование сайта, Сервер, Веб-службы,
   флажок «Включить веб-службы».
2. Включить REST-протокол: там же, Управление протоколами, REST.
3. Создать пользователя службы (например svc_mlreader или moodle_api):
   Администрирование сайта, Пользователи, служебный адрес почты.
4. Создать роль чтения: Администрирование сайта, Пользователи, Разрешения,
   Определение ролей, новая роль (имя произвольное, например ml-reader),
   отметить возможности из таблицы ниже; назначить роль пользователю службы
   в контексте Система (Разрешения, Назначение ролей в системе).
5. Создать внешнюю службу: Сервер, Веб-службы, Внешние службы, Добавить:
   имя (например «Сервис оценки академического риска»), флажки Включена и
   Ограниченная (доступ только перечисленных пользователей). Добавить
   функции из таблицы выше. Авторизованные пользователи: пользователь
   службы.
6. Создать токен: Сервер, Веб-службы, Управление токенами, Создать токен
   для пользователя службы.

## Возможности роли

| Возможность | Что даёт |
|---|---|
| moodle/user:read, moodle/user:viewdetails | чтение профилей по логину |
| moodle/course:view, moodle/course:viewhiddencourses | список курсов, включая скрытые |
| moodle/course:viewparticipants | просмотр списка участников курса (нужна для core_enrol_get_enrolled_users) |
| moodle/site:viewparticipants | то же на уровне системы |
| gradereport/user:view, moodle/grade:viewall | элементы оценок |
| mod/assign:grade, mod/assign:view | задания и сданные работы |
| mod/quiz:view, mod/quiz:viewreports | тесты и попытки |
| mod/forum:viewdiscussion | обсуждения на форумах |

Роль назначается в контексте Система. Если какой-то вызов возвращает отказ
доступа, недостающую возможность добавляют в роль и повторяют запрос.

## Проверка

1. Сведения о службе: открыть в браузере адрес вида
   https://адрес-moodle/webservice/rest/server.php?wstoken=ТОКЕН&wsfunction=core_webservice_get_site_info&moodlewsrestformat=json
   Ответ: JSON с sitename и именем пользователя службы.
2. Чтение профиля: wsfunction=core_user_get_users_by_field, field=username,
   values[0]=любой логин. Ответ: массив (пустой, если логина нет).
3. Участники курса: wsfunction=core_enrol_get_enrolled_users,
   courseid=идентификатор курса. Отказ «Просматривать список участников
   курса» означает отсутствие moodle/course:viewparticipants в роли.

Типовые ошибки: accessexception «Access to the function ... is not allowed»:
функция не добавлена в службу; invalidrecord в таблице external_functions:
функции нет в версии Moodle (так ведёт себя core_log_get_logs в ветке 4.5)
или она не добавлена; errorcoursecontextnotvalid: у роли нет
moodle/course:view, значит ни один курс не доступен службе.

## Переменные окружения проекта

Значения хранятся в локальном .env в корне репозитория (в репозиторий не
попадают, файл в .gitignore):

| Переменная | Значение |
|---|---|
| MOODLE_URL | базовый адрес СЭО, например https://moodle.usaaa.ru (хвост /webservice/rest/server.php добавляется программой) |
| MOODLE_TOKEN | токен службы чтения |
| MOODLE_SALT | соль для хеширования логинов |

## Регламент выгрузки

- Полный обход СЭО (1568 курсов, около 45 минут) выполняется в ночные часы,
  чтобы не нагружать систему в рабочее время (п. 8 ТЗ):
  .venv/Scripts/python -I src/enriched/moodle_etl.py --verbose
- Пробный или выборочный прогон: --limit-courses N или --course-ids
  (список идентификаторов через запятую), --verbose печатает каждый курс.
- Ошибка на одном курсе пропускает курс и печатается, выгрузка
  продолжается; повторный запуск идемпотентен.

## Соответствие студентов и логинов

Логин Moodle равен номеру зачётной книжки (та же механика, что в обработке
1С «Синхронизация зачетных книг с Moodle»). Таблица enriched.student_map
наполняется по совпадению логина с контингентом 1С. В демонстрационном
контуре зачётку имитирует student_id синтетики; при подключении реальной
базы соответствие студента и зачётки даёт расширение 1С, после чего таблицы
enriched.activity_weekly и enriched.activity_agg наполняются действиями
реальных студентов. До этого выгрузка работает в режиме замера покрытия:
доля пользователей Moodle с действиями фиксируется по всей СЭО.
