# Загрузка реальных витрин 1С и замер соответствия с Moodle

Дата выгрузки: 28.11.2026, срез студентов на дату 2026-11-28. Источник:
HTTP-сервис расширения АР_АналитикаРиска над локальной базой
1С:Университет ПРОФ (volkanin-home/uni), публикация IIS
http://localhost/uni/hs/analytics/v1/. Приемник: src/onec_client (клиент
с курсорной пагинацией, страница 10000 строк), SQL приема sql/onec_raw.sql
и sql/onec_cleaned.sql. Карта источников: docs/metadata-mapping.md.

## Решения заказчика, введенные в этой выгрузке

- Порог неудовлетворительной отметки стобалльной шкалы: числа ниже 40
  отрицательные, 40 и выше положительные. Порог реализован в расширении
  (АР_Витрины) и применяется при выводе задолженностей и событий.
- Деление аналитики приказов на академические, финансовые и нейтральные
  утверждено (metadata-mapping.md, п. 4); класс записывается приемником
  в order_class.
- Финансовый блок не загружается: в этой базе данных оплат нет, источник
  будет в базе бухгалтерии.

## Правила персональных данных при приеме (NFR-2, FR-13)

- Номер зачетной книжки хранится только псевдонимом book_hash (sha256 от
  соли MOODLE_SALT и значения без учета регистра, первые 32 символа) и
  заменяется до первой записи в хранилище. Соль и алгоритм общие с ETL
  Moodle (username_hash), поэтому book_hash соединяется с
  enriched.student_map.
- Дата рождения заменяется возрастом age на дату среза; в cleaned
  колоночное поле birth_date опустошается.
- ФИО, паспорта, контакты витринами не отдаются; связь только по UUID.
- Появление незнакомого поля в витрине останавливает загрузку: новые поля
  сервиса проверяются на персональные данные до попадания в хранилище
  (защита сработала дважды на поля entered_at и event_id, которые после
  проверки были добавлены в белый список как безобидные).
- Проверки после загрузки: колонок book_number и birth_date в таблицах
  raw.onec_* нет; дат рождения в cleaned.vs_students 0; возраст заполнен
  у 13185 из 13336 (у остальных дата рождения в источнике пустая);
  псевдонимы книжек заполнены у всех 13336.

## Объемы и время выгрузки

| Витрина | Строк | Время | Примечание |
|---|---|---|---|
| dim/students | 13336 | 9 с | одна запись на студента, срез на дату |
| dim/programs | 3303 | 1 с | документы учебных планов |
| dim/disciplines | 275278 | 220 с | строки планов с дисциплиной |
| fact/movements | 131649 | 17 с | плюс 125 строк приказа без студента, они пропущены |
| fact/grades | 617597 | 222 с | полная история ведомостей с 2012 года |
| fact/debts | 53220 | 56 с | плюс 9745 дубликатов между годовыми окнами, отсечены |
| fact/load | 8865 | 2 с | план-семестр |

Факты выгружаются годовыми окнами (2012-2026): каждый запрос страницы
пересчитывает витрину в 1С заново, меньшие диапазоны обходятся быстрее
(оценки за полную историю: 2793 с одним окном против 222 с годовыми).
Задолженность может попасть в два окна (возникла в одном году, закрыта
в другом), дедупликация по event_id_open.

Согласование объемов: полная выгрузка движений одним окном дала 131774
строки, годовые окна дали 131649 с студентом и 125 строк без студента,
сумма сходится.

Слой cleaned заменен реальными витринами (таблицы vs_*), синтетика
воспроизводится генератором; UCI и OULAD не затронуты. Отличия реальных
данных в cleaned: birth_date пустое, добавлены age, book_hash, faculty,
state, program_id у оценок и долгов, order_kind/analytics/order_class у
движений, control_type у оценок; admission_date выводится из приказов
зачисления; витрина admission пустая (вступительные испытания сервисом
не отдаются), finance пустая.

## Замер соответствия зачетных книжек и логинов Moodle (FR-13)

Методика: действующие студенты берутся из витрины
/mapping/students-books (состояния «Является студентом» и «Задолжник»,
как в существующей обработке «Синхронизация зачетных книжек с Moodle»),
пользователи Moodle из core_user_get_users_by_field по полю username
пакетами по 500 значений. Сравнение через псевдонимы: номер книжки и
логин заменяются sha256 хешем с общей солью, сырые значения живут только
в памяти на время замера. Исполнено src/onec_client/measure_moodle.py
против рабочего Moodle вуза (moodle.usaaa.ru, версия 4.5).

Результат:

| Показатель | Значение |
|---|---|
| действующих студентов (витрина соответствия) | 2052, зачетных книжек 2055 (у 3 студентов две книжки) |
| найдено пользователей Moodle по логину-зачетке | 2055 |
| доля студентов с совпадением книжки и логина | 100% (2052 из 2052) |
| доля по текущему состоянию витрины студентов | 100% (1702 из 1702) |
| записей в enriched.student_map | 2055 |

Витрина соответствия видит все пары студент-книжка, включая исторические
записи по прежним книжкам: у 350 студентов текущее состояние не действующее
(отчисленные слушатели, выпускники), но по прежней книжке пара еще
отмечена действующей; все они тоже совпали с Moodle. Поэтому доля 100%
выполняется по обоим знаменателям.

Показатель H2 (2) из плана экспериментов: доля действующих студентов с
пользователем Moodle по логину-зачетке подтверждена на реальном контуре
на уровне 100% (оценка заказчика 100%).

## Ограничения

- Финансовые витрина и события пустые до подключения базы бухгалтерии.
- Дата внесения записей в источниках отсутствует (entered_at), срез на
  дату наблюдения дополняется запаздыванием на приемнике.
- Витрина admission не наполняется: вступительные испытания расширением
  не отдаются.
- Строки приказов без физического лица (125 строк) пропускаются приемником.
- У 151 студента в источнике пустая дата рождения, возраст не вычислен.
- Реквизиты региона, общежития и льгот в источниках не ведутся
  (metadata-mapping.md, п. 11).
