# Расширение 1С:Университет: HTTP-сервисы выгрузки данных

Реализация доработок по docs/1c_enhancements_tz.md для конфигурации
УниверситетПРОФ_2_2 (версия 2.3.2.28). Расширение называется
АР_АналитикаРиска, назначение «Адаптация», префикс имен АР_. Карта
соответствия предметных полей объектам конфигурации:
docs/metadata-mapping.md.

Каталог является XML-выгрузкой расширения в том виде, в каком её делает
Конфигуратор (исходники совпадают с выгрузкой из информационной базы
последней сборки). Тексты модулей лежат в Ext/Module.bsl, XML-файлы
создает платформа; файлы в UTF-8 с меткой порядка байтов, концы строк
CRLF, как в выгрузках Конфигуратора.

## Состав

| Объект | Тип | Назначение |
|---|---|---|
| АР_АдаптерМетаданных | Общий модуль | запросы к объектам типовой конфигурации; единственное место с их именами |
| АР_Витрины | Общий модуль | сборка витрин, потока событий, соответствия зачетных книжек, курсорная пагинация |
| АР_Сериализация | Общий модуль | JSON, ответы HTTP, приведение значений к строкам |
| АР_Сервис | Общий модуль | разбор параметров запроса, маршруты, обработка ошибок, прием оценок |
| АР_Аналитика | HTTP-сервис | корневой адрес analytics, маршруты с версией /v1 |
| АР_ОценкиРиска | Регистр сведений | прием оценок риска: измерения Расчет, Студент, ДатаРасчета |
| АР_ДоступКСервису | Роль | использование методов сервиса и чтение источников |

Модули серверные, не глобальные. Методы чтения не меняют данные
информационной базы; запись выполняет только прием оценок риска, и только
в регистр АР_ОценкиРиска.

Режим отладки (функция РежимОтладки модуля АР_Сериализация) возвращает
клиенту подробное описание ошибки с модулем и строкой для кода 500. На
рабочей базе его выключают: тексты внутренних исключений наружу не
отдаются, сведения остаются в журнале регистрации.

## Маршруты

Базовый адрес: http://адрес/имя-базы/hs/analytics/v1/. Даты передаются
строками ISO 8601. Ответ во всех методах имеет вид data, meta, errors;
в meta входят count, nextCursor, asOf, schemaVersion. Состав полей каждого
метода возвращает GET /schema.

| Маршрут | Параметры | Что возвращает |
|---|---|---|
| GET /health | | доступность, версия расширения и конфигурации |
| GET /schema | | состав полей всех витрин |
| GET /reference | | наименования справочников: типы, виды и аналитика приказов, отметки, виды контроля и другие |
| GET /dim/students | asOf, cursor, limit | студенты на дату среза, одна запись на студента |
| GET /dim/programs | cursor, limit | учебные планы как программы подготовки, с нормой часов в зачетной единице |
| GET /dim/disciplines | cursor, limit | строки учебных планов: дисциплины семестров с зачетными единицами |
| GET /fact/movements | dateFrom, dateTo, cursor, limit | строки приказов по движению контингента |
| GET /fact/grades | dateFrom, dateTo, cursor, limit | строки ведомостей, история попыток |
| GET /fact/debts | dateFrom, dateTo, cursor, limit | задолженности, возникшие или закрытые в диапазоне |
| GET /fact/finance | dateFrom, dateTo, cursor, limit | оплаты по договорам |
| GET /fact/load | cursor, limit | нагрузка семестра учебного плана |
| GET /events | dateFrom, dateTo, cursor, limit | события: grade, debt_open, debt_closed, payment |
| GET /mapping/students-books | asOf, cursor, limit | пары студент и номер зачетной книжки со состоянием |
| POST /scoring/batch | | прием пакета оценок риска |
| GET /scoring/latest | limit | последние записанные оценки |

Пагинация курсорная: курсор из meta.nextCursor передается параметром
cursor, размер страницы параметром limit (по умолчанию и не более 10000).
Неверные параметры дают код 400 с машиночитаемым текстом ошибки.

## Источники данных

| Витрина | Источник в типовой конфигурации |
|---|---|
| students, mapping | регистр сведений СостояниеСтудентов (срез последних на дату), справочники ЗачетныеКниги и ФизическиеЛица |
| programs | документ УчебныйПлан |
| disciplines, load | документ УчебныйПлан: табличные части ЗаписиУчебногоПлана и ЗЕТПоДисциплинам, свойство КоличествоЧасовВЗЕТ |
| movements | документ Приказы, табличная часть ОбщиеДанные |
| grades, debts, events (grade, debt) | документ Ведомость, табличная часть ДанныеПоАттестации |
| finance, events (payment) | документ ОплатаПоДоговорам |

Решения по данным:

- program_id везде это документ учебного плана, discipline_id это
  дисциплина справочника: так витрины студентов, дисциплин и оценок
  соединяются между собой.
- Зачетные единицы семестра берутся из части ЗЕТПоДисциплинам; если её
  строк для семестра нет, вычисляются как часы семестра, деленные на
  КоличествоЧасовВЗЕТ (36 часов почти во всех планах). Поле
  credits_source показывает источник: plan или calculated.
- Число экзаменов, зачетов и курсовых в нагрузке считается по
  наименованию вида нагрузки или контроля справочников.
- Задолженности выводятся из отметок ведомостей: отрицательная отметка
  (неудовлетворительно, не зачтено, неявка) открывает задолженность,
  следующая положительная отметка по тому же ключу (студент, учебный
  план, дисциплина, период контроля) закрывает. Для этого методы debts и
  events читают всю историю по ключам, задетым диапазоном.
- Приказы классифицируются по полю аналитики (справочник
  АналитикаТиповПриказа) и наименованию вида приказа: академические
  («За академическую неуспеваемость», «Невыполнение учебного плана»,
  «Как не прошедших ГИА»), финансовые («Невыполнение условий договора об
  оказании платных образовательных услуг»), остальные нейтральные.
  Перечень значений возвращает GET /reference.

Идентификаторы событий производные от записей источников и не меняются
при повторной выгрузке: grade:UUID ведомости:номер строки,
debt-open, debt-closed, payment:UUID документа.

## Загрузка расширения в информационную базу

Удобнее всего набором навыков 1c-skills (реестр баз в файле
.v8-project.json в корне репозитория, в git не попадает):

    /db-load-xml src/1c_ext uni -Extension АР_АналитикаРиска -UpdateDB
    /db-cfe-admin check uni -Name АР_АналитикаРиска
    /db-dump-xml uni src/1c_ext -Extension АР_АналитикаРиска

Те же операции пакетным режимом Конфигуратора (запускать из cmd или
PowerShell, не из Git Bash):

    "C:\Program Files\1cv8\8.3.27.2342\bin\1cv8.exe" DESIGNER /S "сервер\база" /N пользователь /P пароль /DisableStartupDialogs /LoadConfigFromFiles C:\work\inno_grad\src\1c_ext -ExtensionАР_АналитикаРиска /Out C:\temp\load.log
    "C:\Program Files\1cv8\8.3.27.2342\bin\1cv8.exe" DESIGNER /S "сервер\база" /N пользователь /P пароль /DisableStartupDialogs /UpdateDBCfg -ExtensionАР_АналитикаРиска /Out C:\temp\db.log

Правила, проверенные на практике:

1. Ключ расширения пишется через дефис и без пробела: -ExtensionИмя.
   Вариант через косую черту с пробелом (/Extension Имя) Конфигуратор
   молча игнорирует и применяет команду к основной конфигурации.
2. Первая команда создает расширение, если его еще нет, и загружает
   файлы; вторая обновляет конфигурацию базы данных расширения.
3. В графическом Конфигураторе загрузка выполняется из окна конфигурации
   расширения (Конфигурация, Расширения конфигурации, открыть расширение,
   затем Загрузить конфигурацию из файлов), а не из окна основной
   конфигурации.
4. Расширение, впервые попавшее в базу загрузкой из файлов, создается с
   включенным безопасным режимом; сервису он не мешает. Идентификатор
   принятого из типовой конфигурации языка должен быть уникальным у
   каждого расширения: совпадение дает критическую ошибку применения
   (конфликт внутренних идентификаторов), и сервис не публикуется.
5. Пакетный файл для cmd сохраняется с концами строк CRLF.

Выгрузка расширения из базы для сверки приведена выше (/db-dump-xml); после
изменения модулей исходники сверяют с выгрузкой: тексты модулей должны
совпадать побайтно.

## Публикация на веб-сервере

Расширение с HTTP-сервисом публикуется автоматически, если в файле
публикации (default.vrd) для httpServices задан атрибут
publishExtensionsByDefault="true". Если сервис не отвечает кодом 404 от
модуля расширения веб-сервера, первым делом проверяют, применяется ли
расширение (ошибку применения показывает Конфигуратор при открытии базы).
Проверка из внутреннего сегмента:

    curl -u пользователь:пароль "http://localhost/uni/hs/analytics/v1/health"
    curl -u пользователь:пароль "http://localhost/uni/hs/analytics/v1/dim/students?asOf=2026-11-28&limit=5"
    curl -u пользователь:пароль "http://localhost/uni/hs/analytics/v1/fact/grades?dateFrom=2026-01-01&dateTo=2026-02-28&limit=5"

## Права

Пользователь интеграции получает роль АР_ДоступКСервису: использование
методов сервиса, чтение справочников зачетных книг, физических лиц и
справочников метода /reference, документов Ведомость, Приказы,
ОплатаПоДоговорам, УчебныйПлан, регистров СостояниеСтудентов и УчебныйПлан,
чтение и запись регистра АР_ОценкиРиска. Отладка велась от пользователя с
полными правами; отдельный пользователь с ограниченной ролью еще не
проверялся.

## Ограничения первой итерации

- Дата внесения записи в источниках отсутствует: entered_at пустое, хвост
  записей отсекается запаздыванием на стороне приемника.
- Финансы: в тестовой базе нет документов оплат по договорам, витрина
  finance пуста. Источник финансовых событий будет взят из базы
  бухгалтерии.
- Реквизит Регион справочника ФизическиеЛица есть в основной
  конфигурации, но отсутствует в конфигурации базы данных тестовой базы:
  сервис выполняет запрос без региона (поле region пустое). Поля hostel и
  privilege пустые: в источниках не ведутся.
- Отметки стобалльной шкалы (числа в ведомостях) не относятся ни к
  положительным, ни к отрицательным: порог неудовлетворительной отметки
  нужно согласовать.
- Служебные отметки ведомостей («Загрузил работу», «Не загрузил работу»,
  «Удален») не учитываются при выводе задолженностей.
- Финансовые отчисления слушателей дополнительного образования (ДО и
  ШАХТ) попадают в movements наряду с отчислениями студентов: приемник
  отбирает приказы типа «Отчисление» по действующим студентам.
- Пагинация выполняется в памяти по строковому ключу. Первое обращение к
  витринам студентов и дисциплин занимает 7-8 секунд, дальше быстрее.
- Фоновая выгрузка больших объемов (/export/jobs из базовой постановки)
  не реализована: диапазон дат дробится на части.
