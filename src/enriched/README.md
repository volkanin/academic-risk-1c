# Слой enriched (блок 4.1)

Внешние данные, дополняющие признаки ML: открытые сведения о направлениях
подготовки и активность студентов Moodle. DDL: sql/enriched.sql. Персональных
данных слой не содержит (NFR-2, п. 9 ТЗ).

## Веб-скрейпинг направлений подготовки

scrape_programs.py читает раздел «Сведения об образовательной организации»
официального сайта вуза (обязательный по приказу Рособрнадзора, размечен
микроразметкой schema.org):

- sveden/education: 34 образовательные программы, 16 кодов направлений
  (код, название, профиль, уровень, формы обучения, сроки);
- sveden/budget: финансовое обеспечение по источникам и год.

Сырые страницы сохраняются в data/external/usaaa (в репозиторий не входят),
извлечённые таблицы загружаются в enriched.programs_info и
enriched.finance_info идемпотентно (TRUNCATE + INSERT). Повторный запуск
обновляет данные с новой датой scraped_at.

## Контекст направления

Представление enriched.v_program_context даёт признаки на уровне кода
направления: число программ вуза по коду, уровни, наличие очной формы,
флаг творческого профиля (архитектура и искусство, коды 07.* и 54.*).
enriched.v_student_program_context соединяет контекст со студентами по коду,
разобранному из заголовка программы. Направления, которых нет в реальном
вуза (синтетика включает инженерные коды для разнообразия), остаются с
пустым контекстом, сам факт отсутствия тоже признак.

## Moodle ETL

moodle_etl.py собирает активность студентов по стандартным веб-службам
Moodle (REST, токен внешней службы с функциями чтения, FR-13): события по
курсам (core_log_get_logs), оценки, сданные работы, попытки тестов.
Ключ соответствия: логин Moodle равен номеру зачётной книжки (механика
существующей обработки 1С «Синхронизация зачетных книг с Moodle»); в
демонстрационном контуре зачётку имитирует student_id синтетики, при
подключении реальной базы соответствие приходит из расширения 1С.

Псевдонимизация: из профиля Moodle читается только логин, он сразу
заменяется sha256-хешем с солью (MOODLE_SALT в .env), в enriched хранятся
только хеши и идентификаторы студентов; имена и почты не выгружаются.
Недельная динамика: события привязываются к неделям семестра по учебному
календарю студента (semester_week), неделя 0 это межсессионный период.
Оценки, работы и попытки без дисциплинарной привязки (она отложена в
backlog) учитываются суммарно за весь период. ETL печатает сводку
покрытия: доля студентов контингента с активностью, замер через API для
проверки H2 на реальном контуре.

Таблицы результата: enriched.student_map, enriched.activity_weekly
(семестр, неделя, события, активные дни, курсы) и enriched.activity_agg.

## Демонстрационный контур Moodle

moodle_mock.py поднимает локальный эмулятор REST-служб Moodle на 127.0.0.1:8010
с фикстурами в формате Moodle (два курса, пять студентов контингента,
события по неделям семестров, оценки, работы, тесты). ETL работает через
настоящий REST-обмен (POST с wstoken), поэтому механика выгрузки проверена
до подключения реального сервера; реальный Moodle задаётся адресом и токеном
в .env, эмулятор больше не нужен. Локальные запросы идут без системного
прокси (переменные окружения среды их перехватывали).

## Запуск

```
.venv/Scripts/python -I src/enriched/scrape_programs.py
.venv/Scripts/python -I src/enriched/moodle_mock.py            # эмулятор в отдельном окне
.venv/Scripts/python -I src/enriched/moodle_etl.py --mock      # демонстрационный контур
.venv/Scripts/python -I src/enriched/moodle_etl.py             # реальный Moodle: MOODLE_URL и MOODLE_TOKEN в .env
```
