# Приемник HTTP-сервиса расширения 1С (витрины, события, оценки)

Клиентская сторона интеграции: расширение АР_АналитикаРиска (src/1c_ext)
отдает витрины по HTTP, этот модуль выгружает их в хранилище проекта.
Файловая выгрузка не используется, потоки описаны в docs/1c_enhancements_tz.md.

## Состав

| Файл | Назначение |
|---|---|
| client.py | клиент сервиса: все маршруты с курсорной пагинацией, повторы при сбоях, дедупликация событий по event_id, отправка оценок POST /scoring/batch |
| load.py | загрузка реальных витрин в слой raw (raw.onec_*) и слой cleaned (таблицы vs_* вместо синтетики) |
| measure_moodle.py | замер соответствия номеров зачетных книжек и логинов Moodle, наполнение enriched.student_map |

Запуск:

    .venv/Scripts/python -I src/onec_client/load.py
    .venv/Scripts/python -I src/onec_client/measure_moodle.py

Адрес и учетные данные в .env: 1C_BASE_URL, 1C_USER, 1C_PASSWORD,
MOODLE_SALT (общая соль псевдонимизации), MOODLE_URL и MOODLE_TOKEN для
замера. Локальные запросы идут напрямую, без системного прокси.

## Правила персональных данных при приеме (NFR-2, FR-13)

Персональные данные не записываются ни в базу, ни в журналы, ни в
репозиторий, ни в тесты:

- номер зачетной книжки заменяется псевдонимом book_hash до первой записи
  в хранилище: sha256 от соли MOODLE_SALT и значения без учета регистра,
  первые 32 символа, тот же алгоритм, что и для логина Moodle
  (username_hash), поэтому book_hash соединяется с enriched.student_map;
- дата рождения заменяется возрастом age на дату среза;
- ФИО, паспорта, контакты витринами не отдаются, связь только по UUID;
- неизвестные поля витрины останавливают загрузку: новые поля сервиса
  проходят проверку на персональные данные до попадания в хранилище.

## Решения по данным

- Слой cleaned замещается реальными витринами (контракты витрин расширения
  писались по полям cleaned, docs/1c_enhancements_tz.md); синтетика
  воспроизводится генератором src/data/generator.py и sql/schema.sql +
  sql/layers.sql. UCI и OULAD не затрагиваются.
- SQL приема: sql/onec_raw.sql (таблицы raw.onec_*) и sql/onec_cleaned.sql
  (перенос в vs_* с правилами ПДн и единой шкалой оценок).
- В raw семестр хранится дважды: исходное наименование периода контроля и
  разобранный номер semester_num; класс приказа order_class вычисляется
  приемником по утвержденному делению аналитики (docs/metadata-mapping.md,
  п. 4): академические, финансовые, нейтральные.
- Оценки: единая шкала для именованных отметок (Отлично 5, Хорошо и
  Зачтено 4, Удовлетворительно 3, Неудовлетворительно и Не зачтено 2),
  числовые отметки стобалльной шкалы остаются числом в grade и
  классифицируются порогом 40 в is_pass (решение заказчика 28.11.2026);
  Неявка дает grade_numeric пустое значение и признак absent.
- Дата зачисления студента выводится из приказов зачисления
  (cleaned.vs_students.admission_date); витрина admission остается пустой.
- Финансовая витрина не загружается: в этой базе данных оплат нет, источник
  появится в базе бухгалтерии; cleaned.vs_finance опустошается.
- entered_at в источниках отсутствует: даты внесения записей заменяются
  запаздыванием на приемнике (базовая постановка, п. 6.3).
- Идентификатор расчета для POST /scoring/batch это UUID пакета оценок;
  повторная отправка пакета с тем же calculationId заменяет набор расчета
  в регистре АР_ОценкиРиска (идемпотентность на стороне 1С).
